# 01｜固定版本與完整玩法清冊


依 Master 工作；本階段先做可追蹤的規則清冊，不直接堆功能。

1. 建立 ruleset-manifest：reference game、確切 version/build、DLC／content packs、平台差異、遊戲速度、模式、人口上限、地圖尺寸／種子，以及資料來源與信心。
2. 將目標拆成「機制完整」「內容完整」「模式完整」「品質完整」。完整文明、單位、建築、科技、文明加成、團隊加成、特殊升級、地圖腳本、模式與戰役目錄，必須有獨立 entry，不以範例清單代替全集。
3. 建立 traceability：每項 feature → requirement → data IDs → implementation files → tests → runtime evidence。沒有證據不能標示 verified。
4. 定義可玩切片：兩方地圖、村民與四資源、人口／建造、四時代研究通路、至少近戰／遠程／攻城三類、基本 AI、迷霧、勝敗、重新開始。每個暫定參數標 design_default。這只是切片，不是完整移植。
5. 完整目標必須額外涵蓋所有選定內容與跨系統互動，包括運輸／駐軍／轉化／科技互斥／隊伍／海圖／交易／特殊勝利。
6. 定義「功能等價」與「精確原作對照」兩種驗收。自訂戰役可驗證戰役引擎完整，但不能宣稱原作劇情內容已移植。
7. 建立 schema／驗證器：ID 唯一、參照存在、科技圖無循環或有明確支援、成本／時間／人口值有效、文明不可用項不出現在可用列表中。

來源不足：建立待核對欄位，繼續不依賴未知值的工程；不擅自選定最新 DLC、不聲稱數值一致。原作內容總數未知時，coverage denominator 必須顯示 unknown，不能顯示 100%。

交付：manifest、machine-readable ledger、規則 schema、缺口報告、階段依賴圖、可重跑的資料驗證命令。驗收至少包含重複 ID、懸空科技、負成本與未知版本四類失敗案例。
