# 05｜尋路、避讓、隊形與卡住恢復


建立確實能支援 RTS 群體移動的導航系統；不能以所有單位直線追目標代替。

- 區分格網通行、粗略區域連通、個體半徑／大型單位、動態阻擋。可採階層式 A* 和局部避讓，演算法選擇需有 workload evidence，不能混用一堆名詞卻無完整行為。
- 命令含 move、attackMove、patrol、follow、stop、queued waypoints、guard／站位命令（按對照範圍）。目標不可達時，回傳明確狀態與附近合法停止點，而不是無限原地抖動。
- 群組有穩定 slot 分配、到達半徑、隊形朝向及前後排規則。狹道收縮、通過後展開；大隊不因最後一名卡住就全部永久停下。
- 動態避讓、穿越友方的允許條件、建築入口／出口、門的開關與外交、採集站點容量、駐軍／運輸集合都需共同規則。
- 建造落地與拆除、砍樹、門鎖、橋／地形變化更新 nav；不得把模型碰撞網格當導航唯一依據。
- 有 bounded replanning、stuck detection、分批計算及取消機制。工作 budget 用確定性的節點數／tick，不用執行毫秒決定 sim 結果；不能瞬移或穿牆當作修復。
- 近戰包圍需要合法攻擊位置，不全部搶同一個座標；遠程單位到達射程後停在可用位置，不能排成穿模堆疊。

測試：百人通過單一城門、雙向窄路、大型攻城器械、採集者圍資源、撤銷長途命令、目的地被新牆封死、船隻靠岸／互相避讓、隊形遇阻後復原。記錄 p95 path nodes、等待 tick 與 stuck 數量；不得宣稱壓力測試通過而只測兩個單位。
