# 08｜建築、施工、人口、升時代與科技樹


將建築、施工與科技製作成資料驅動的完整系統。

- Placement 使用明確 footprint、地形／水岸條件、阻擋／碰撞類別、必要距離與視野規則。施工地基何時阻擋、單位如何離開、何時扣費、失敗是否退款都可測試。
- 施工進度來自實際工作者／效率，連動積木分段搭建；建造者要有可到達工作點。多村民建造、暫停、接手、取消、受攻擊、未完成建築摧毀需具明確規則。
- 人口 used、reserved、cap、hard cap 分開定義。訓練佇列何時扣費／保留人口、人口不足如何等待、房屋被毀、佇列取消退款與出兵出口受阻要處理。
- 生產與科技佇列支援重排／取消的允許範圍、集結點與相依條件；不可一個 frame 重複生產或研究。同種研究不能在兩棟建築重複扣費。
- 四時代升級含資源、前置建築／科技、研究時間與狀態限制；升級完成觸發內容解鎖，但既有單位／建築數值如何更新由 upgrade policy 決定。
- 科技資料含 prerequisite、exclusive group、affected classes、modifier stacking/order、文明可用性、global／local scope、對既有與未來單位的影響。
- 內容類型覆蓋城鎮中心、住宅、資源收集建築、農田、市場、鐵匠舖、兵營、靶場、馬廄、攻城器工坊、學院／大學、修道院、城堡、防禦塔、城牆、城門、碼頭與世界奇觀等；這是系統分類，不代替指定版本的完整建築清單。
- 駐軍／出城、城門開關／上鎖／外交通行、維修、刪除建築、殘骸清理都使用權威命令。射箭／治療等駐軍效果不可只做視覺。

交付建築／科技 schema、樹狀驗證器、建造命令、人口／queue manager、施工視覺對接。驗收前置缺失、同 tick 競爭資源、出口封鎖、城門關閉時單位處理、人口下降、升級前後數值、取消與存讀一致。
