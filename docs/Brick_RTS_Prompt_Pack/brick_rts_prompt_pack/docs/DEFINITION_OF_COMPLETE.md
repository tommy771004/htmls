# 如何判斷「完整玩法移植」

## 四種不同的完成度

| 層級 | 完成條件 | 不能當替代證據的事 |
|---|---|---|
| 機制完整 | 固定版本的每項目標玩法、例外與互動均可執行並驗證 | 有按鈕、有類別、有註解、只會模擬 happy path |
| 內容完整 | 指定文明／兵種／建築／科技／地圖／模式等逐項核對，不存在未說明缺項 | 只做兩文明或幾個代表模型後宣稱原作全部內容 |
| 美術完整 | 資產清冊的模型、LOD、工作／戰鬥／施工／受損狀態及玩家辨識均完成 | 靜態場景截圖、盒子占位、只有材質改色 |
| 品質完整 | 操作、存讀、重播、多客戶端、目標硬體與長局測試達到已同意門檻 | 單元測試數、程式可編譯、未執行的 benchmark |

精確原作對照還需要指定 version/build、資料來源與對照測試。版本或完整清單未知時，不存在可誠實計算的「100% 原作覆蓋率」。

## 核心驗收路徑

- 經濟：採集→攜帶→返還→建造→擴人口→升時代→研究→造兵。
- 戰鬥：偵查→合法接敵→相剋／射程／科技→攻城→防守／撤退→勝敗→再開局。
- 海圖：漁業→海軍→運輸登陸→跨海勝利，含乘員與海岸失敗情境。
- 宗教／交易：治療／轉化→所有權與人口／科技更新；遺跡存入→產出／勝利；商隊→實際往返收益。
- 複雜狀態：途中存讀、相同命令重播、城門／科技／人口／招降／運輸互動。
- 多人：獨立客戶端、權威驗證、fog 封包過濾、延遲與斷線重連、完整對局。
- 模式／創作：原創戰役進度、情境編輯／匯出／匯入／playtest、特殊勝利與 trigger 恢復。

## 標籤規則

- Prototype：工程／美術概念驗證。
- Vertical slice：一條可玩的完整閉環，內容和規模明確有限。
- Feature-complete for agreed scope：已確認清單的系統功能完整，內容／品質仍可有明示缺口。
- Complete for pinned ruleset：固定範圍的內容、規則、美術和品質全部達標，有可重跑證據。

原創戰役驗證戰役系統，不等於原作故事全部重製；自訂平衡數值支援遊戲，不等於與 DE 數值相同；多人房間支援協定不等於已驗證最大人口規模。

## 不允許的完成度灌水

不能把 block 的功能改成 excluded 後宣稱 100%；不能以新增文件取代要求的程式；不能將 graphics placeholder 標為高細節完成；不能把「未發現 bug」說成「沒有 bug」。沒有真實執行的測試，只能列 planned／not_run。
