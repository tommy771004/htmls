# 實作順序與階段門檻

這不是要求 coding agent 一輪同時生成整個遊戲。每次提供 Master、當前階段、相關已確認資料與 ledger，要求可執行的垂直成果。

| 順序 | 使用提示詞 | 本階段必須能證明的事 |
|---|---|---|
| A. 固定範圍 | 00、01 | 版本／內容範圍與未知項可追蹤，schema 可拒絕錯誤資料。 |
| B. 技術骨架 | 02 | 無畫面也可跑 tick、下命令、存狀態、重播 hash。 |
| C. 積木視覺與戰場 | 03、04 | 實際模型、地形、資源、迷霧；不是只產出美術文字。 |
| D. 基本操作 | 05、06 | 選取、編組、尋路、狹道與 HUD 操作可測。 |
| E. 首個完整對局 | 07、08、09，加 12 的基本 AI | 能經濟發展、升時代、造兵、攻城、判勝敗、再開局。以兩方小範圍資料起步，明標 vertical slice。 |
| F. 系統擴充 | 10、11、12 完整版 | 海軍／運輸、貿易、宗教、文明差異、完整 AI 行為，不只增加模型。 |
| G. 可恢復遊戲 | 13 | 中途存讀後繼續、重播一致性、損壞檔處理。 |
| H. 多人 | 14 | 真正多客戶端、伺服器權威、迷霧過濾、重連與完整對局。 |
| I. 多模式與內容工具 | 15 | 特殊勝利、原創戰役、trigger、編輯器到 playtest。 |
| J. 完整品質與規模 | 16、17、18 | 音效／特效、美術全集、實機效能與完整內容逐項稽核。 |
| 持續迴圈 | 19 | 每一個可玩里程碑都從第一次使用流程測到卡點，再修正並回歸。 |

## 提早做、不能拖到最後的事情

03 的美術預算、13 的序列化邊界、14 的命令／視野權限、17 的效能 profiler 要在架構階段預留，不能前面全部耦合到畫面後才補。17 的完整硬體驗收可以後置，但 smoke benchmark 從 D 階段開始。

## 每輪實際交付格式

1. 修改摘要與實作檔案，說明既有功能如何保留。
2. 可執行命令、依賴與啟動／遊玩路徑。
3. 實際執行的測試與原始結果，未執行的逐項列出。
4. 本階段的 bug、限制、ledger 狀態、下一個依賴。

不得把「規格已寫」「程式可編譯」「測試檔已建立」「單元測試通過」「實際玩過」「目標筆電跑過」混成同一種完成度。

## 何時可擴充

先修無法啟動、黑屏、無法選取／派工、單位無法接敵、勝敗無法觸發、重開失效及資料遺失。擴充不得掩蓋既有阻塞。資料基準缺失不阻止工程原型，但會阻止「精確對照／完整移植」的聲明。
