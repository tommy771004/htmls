# 網頁積木 RTS：完整玩法開發提示詞包

目的：製作在桌面瀏覽器執行、玩法以指定版本《世紀帝國 II：決定版》為對照、使用原創樂高風格積木美術的即時戰略遊戲。

這是開發提示詞與驗收規格，不是遊戲程式、官方移植、完整原作資料庫或已通過的測試報告。包內數字是提議的設計／效能目標，並非原作參數或實測結果。

## 使用方式
1. 把本包放進開發專案，例如 `project-spec/`，先閱讀 `docs/BUILD_ORDER.md`。
2. 第一次把 `prompts/00_PROJECT_MASTER.md` 與 `prompts/01_RULESET_SCOPE_AUDIT.md` 一起交給 coding agent。
3. 後續每次只指派一個階段，保留 Master、已建立的規則表與相關規格；不需要每輪貼整個合併檔。
4. 每階段必須產出程式、測試、操作方式、變更清單與未完成項。只修改說明文件不算實作完成。
5. 完成一段可玩流程後，執行 `19_FIRST_TIME_USER_FIX_LOOP.md`，先修阻塞再擴充。
6. 把每階段狀態記入 feature ledger。所有初始條目都尚未實作／驗證。

範例指令：
> 請遵守 00_PROJECT_MASTER，執行 07_ECONOMY_VILLAGERS。先檢查既有程式，再修改必要檔案，執行可用的測試，記錄證據並更新 ledger。不要重建已完成模組，也不要把 mock 或註解當成遊戲功能。

## 基準與邊界
- 目前未指定 DE 的版本／build、擴充內容和精確規則資料，也未連網核對當前內容。因此不能宣稱覆蓋最新 DE 的全部文明、平衡數值與情境。
- 必須先固定玩法對照版本。未知資料保留 `unverified`；可玩測試採用的自訂參數標示 `design_default`，不能冒充原作數值。
- 原作程式、美術、音樂、配音、戰役文字等不直接搬用。使用自製或有適當使用權的素材，保留來源與授權紀錄。
- LEGO 在本規格中指使用者要求的積木視覺方向；成品採原創積木資產，不暗示 LEGO 或 Age of Empires 官方授權／合作。
- 精確規則、完整內容、完整可玩流程、多人與實機效能是不同驗收項，不得互相替代。

## 目標環境
暫沿用先前網頁 3D 專案的中階筆電、16GB RAM、整合式 GPU 作為基線；這是暫定測試裝置，不是已量測結果。以桌面 Chrome、Edge、Firefox、Safari 的實測結果建相容性表。WebGL2 作為渲染基線；不可用時顯示可理解的錯誤，不留黑屏。手機版不作首版承諾。

## 套件內容
- `prompts/00`：共同任務、工程限制與交付契約。
- `prompts/01–18`：規則、美術、模擬、完整玩法與發行驗收。
- `prompts/19`：第一次使用的反覆修正流程。
- `docs/`：實作順序、美術細節矩陣、完整定義。
- `templates/`：功能清冊、規則清冊、資產清冊及測試證據模板。
- 同時提供單一合併 Markdown，方便完整閱讀；實作時仍建議逐階段使用。

# 實作順序與階段門檻

這不是要求 coding agent 一輪同時生成整個遊戲。每次提供 Master、當前階段、相關已確認資料與 ledger，要求可執行的垂直成果。

| 順序 | 使用提示詞 | 本階段必須能證明的事 |
|---|---|---|
| A. 固定範圍 | 00、01 | 版本／內容範圍與未知項可追蹤，schema 可拒絕錯誤資料。 |
| B. 技術骨架 | 02 | 無畫面也可跑 tick、下命令、存狀態、重播 hash。 |
| C. 積木視覺與戰場 | 03、04 | 實際模型、地形、資源、迷霧；不是只產出美術文字。 |
| D. 基本操作 | 05、06 | 選取、編組、尋路、狹道與 HUD 操作可測。 |
| E. 首個完整對局 | 07、08、09，加 12 的基本 AI | 能經濟發展、升時代、造兵、攻城、判勝敗、再開局。以兩方小範圍資料起步，明標 vertical slice。 |
| F. 系統擴充 | 10、11、12 完整版 | 海軍／運輸、貿易、宗教、文明差異、完整 AI 行為，不只增加模型。 |
| G. 可恢復遊戲 | 13 | 中途存讀後繼續、重播一致性、損壞檔處理。 |

| J. 完整品質與規模 | 16、17、18 | 音效／特效、美術全集、實機效能與完整內容逐項稽核。 |
| 持續迴圈 | 19 | 每一個可玩里程碑都從第一次使用流程測到卡點，再修正並回歸。 |

## 提早做、不能拖到最後的事情

03 的美術預算、13 的序列化邊界、14 的命令／視野權限、17 的效能 profiler 要在架構階段預留，不能前面全部耦合到畫面後才補。17 的完整硬體驗收可以後置，但 smoke benchmark 從 D 階段開始。

## 每輪實際交付格式

1. 修改摘要與實作檔案，說明既有功能如何保留。
2. 可執行命令、依賴與啟動／遊玩路徑。
3. 實際執行的測試與原始結果，未執行的逐項列出。
4. 本階段的 bug、限制、ledger 狀態、下一個依賴。

不得把「規格已寫」「程式可編譯」「測試檔已建立」「單元測試通過」「實際玩過」「目標筆電跑過」混成同一種完成度。

## 何時可擴充

先修無法啟動、黑屏、無法選取／派工、單位無法接敵、勝敗無法觸發、重開失效及資料遺失。擴充不得掩蓋既有阻塞。資料基準缺失不阻止工程原型，但會阻止「精確對照／完整移植」的聲明。

# 00｜共同總提示詞


你是資深 RTS 遊戲工程師、技術美術、關卡設計師與測試工程師。請在既有專案中依序製作一款桌面瀏覽器可玩的中世紀即時戰略遊戲。玩法以使用者指定版本的《世紀帝國 II：決定版》為逐項對照，美術採原創、高細節、可辨識的樂高風格積木模型。

## 不可變目標
- 不做展示頁、擺拍城堡或只有移動與砍人的 demo。最終必須有從新遊戲、發展經濟、升級、造兵、戰鬥到勝負與再開一局的完整閉環。
- 最終範圍包含經濟、四時代、科技、建造、陸戰、海戰、貿易、宗教／遺跡、文明差異、AI、遊戲模式、儲存／讀取、重播、多人、原創戰役與情境編輯器；精確項目由固定版本的 scope ledger 管理。
- 先完成兩方對戰的可玩切片，再擴充；切片不能標示為完整 DE 移植。完整文明／單位／科技／模式清單必須另行核對，不可憑印象列幾項就宣稱全部。
- 美術不是普通方塊套鮮豔材質：必須有統一積木模數、凸點、接縫、斜面、門窗、瓦片、機械關節、施工狀態、工作動畫與損壞／修復狀態。

## 工程架構
採 TypeScript。建議 Vite + Three.js，React 只處理選單／HUD，權威遊戲狀態不可放在 React 元件內。這是指定的架構方案，不是對最新版本的宣稱；初始化時實際確認並鎖定可用版本、引擎與依賴。

- packages/sim：不依賴 DOM、Three.js、React 或音訊的規則引擎。
- packages/content：具版本、schema、穩定 ID、驗證器的文明／單位／建築／科技／地圖／模式資料。
- apps/web：輸入、渲染、資產、HUD、音效；單人 sim 可置於 Web Worker。
- apps/server：後期多人權威伺服器；沿用相同規則引擎。
- tests：單元、跨系統整合、重播一致性、真實瀏覽器互動、效能場景。

模擬固定 tick（初始提議 20 Hz，需量測），畫面獨立插值。使用指定 PRNG、穩定排序、可重現命令與狀態序列化。動畫、粒子、螢幕 FPS、系統時間不能決定戰鬥或資源結果。路徑／碰撞採遊戲專用系統，不將每塊積木當獨立物理剛體。

## 資料與對照
先建立 ruleset-manifest、feature-ledger、asset-manifest 與 completeness matrix。每個原作對照值標明版本、來源／測試證據與 verification status。未知值不得杜撰；測試用自訂值標示 design_default。沒有可用原作基準時可繼續做原創規則切片，但不可宣稱精確移植。

## 美術與效能
中階筆電、16GB RAM、內顯為暫定目標。使用 LOD、instancing、幾何合併、材質共用、資源池與視野剔除；細節保留在可看見且會被玩家辨識的地方。不可為降低負載偷偷刪兵、削弱 AI、縮小人口上限或跳過權威模擬。

## 開發與交付契約
每階段先讀既有檔案，沿用已驗證架構，避免無關重寫。必須提交本階段程式、資料、測試、執行命令、操作步驟、修改理由與剩餘項。提供 npm install/dev/build/test 等實際可用命令及 lockfile，不可寫不存在的指令。

證據分開記錄：程式碼存在、單元測試、整合測試、瀏覽器操作、目標硬體量測。沒有執行的項目標示未驗證，不可編造通過數字、畫面、FPS、多人連線結果或授權狀態。只改註解、stub、placeholder、TODO、假按鈕不能算完成；阻塞需明示，仍交付已完成的可執行子範圍。

# 01｜固定版本與完整玩法清冊


依 Master 工作；本階段先做可追蹤的規則清冊，不直接堆功能。

1. 建立 ruleset-manifest：reference game、確切 version/build、DLC／content packs、平台差異、遊戲速度、模式、人口上限、地圖尺寸／種子，以及資料來源與信心。
2. 將目標拆成「機制完整」「內容完整」「模式完整」「品質完整」。完整文明、單位、建築、科技、文明加成、團隊加成、特殊升級、地圖腳本、模式與戰役目錄，必須有獨立 entry，不以範例清單代替全集。
3. 建立 traceability：每項 feature → requirement → data IDs → implementation files → tests → runtime evidence。沒有證據不能標示 verified。
4. 定義可玩切片：兩方地圖、村民與四資源、人口／建造、四時代研究通路、至少近戰／遠程／攻城三類、基本 AI、迷霧、勝敗、重新開始。每個暫定參數標 design_default。這只是切片，不是完整移植。
5. 完整目標必須額外涵蓋所有選定內容與跨系統互動，包括運輸／駐軍／轉化／科技互斥／隊伍／海圖／交易／特殊勝利。
6. 定義「功能等價」與「精確原作對照」兩種驗收。自訂戰役可驗證戰役引擎完整，但不能宣稱原作劇情內容已移植。
7. 建立 schema／驗證器：ID 唯一、參照存在、科技圖無循環或有明確支援、成本／時間／人口值有效、文明不可用項不出現在可用列表中。

來源不足：建立待核對欄位，繼續不依賴未知值的工程；不擅自選定最新 DLC、不聲稱數值一致。原作內容總數未知時，coverage denominator 必須顯示 unknown，不能顯示 100%。

交付：manifest、machine-readable ledger、規則 schema、缺口報告、階段依賴圖、可重跑的資料驗證命令。驗收至少包含重複 ID、懸空科技、負成本與未知版本四類失敗案例。

# 02｜權威模擬、命令與可重現性


依 Master 建立能在無畫面環境執行的純 TypeScript RTS 模擬核心。

- 使用穩定 entity ID 與可序列化 component／state。資料包含玩家、外交、資源、人口、位置、路徑、命令佇列、工作、戰鬥、建築、科技、視野與勝利條件。
- 定義 CommandEnvelope：protocolVersion、rulesetHash、playerId、sequence、targetTick、commandType、payload。命令先驗證所有權、目標、科技、資源、人口、地形與模式合法性，再原子提交。
- 同 tick 的命令與系統更新有明確穩定排序。跨瀏覽器一致性敏感值用固定點／整數和指定算術規則；避免依賴不穩定集合順序或超越函數。PRNG 演算法與所有 state／stream IDs 可保存。
- 固定模擬 tick 與可控制的遊戲速度。暫停、失焦、背景分頁 timer throttling、Worker lag、超載均有明確策略；單人可暫停，多人由伺服器持續決定，不能自行跳 tick。
- Path jobs 必須按 deterministic tick budget 推進，不可讓 wall-clock 完成先後改變結果。視覺資產非同步載入不得改變 entity 或 RNG。
- Web Worker 使用明確訊息協定與 transferable buffers；尚未有 cross-origin isolation 時不依賴 SharedArrayBuffer。主執行緒不得每 frame 複製整個世界。
- 跨執行個體比較 canonical state hash，排除鏡頭、動畫、粒子與插值；包含待執行事件、路徑 frontier、RNG、命令與所有權威狀態。
- 例外要帶 tick／command ID／entity ID；不得 catch 後吞掉錯誤並繼續偽裝正常。

交付：sim API、命令 schema、headless runner、tick profiler、state serializer。測試相同 seed＋命令得相同 hash、不同更新頻率不改結果、重複／過期命令、非法控制敵方、資源扣除原子性、10000 ticks 重播一致性。跨瀏覽器測試未執行需明示。

# 03｜高細節樂高風格積木美術


依 Master 與 docs/ART_DETAIL_MATRIX.md 建立可量產的原創積木資產系統，不是單張概念圖。

## 整體視覺
中世紀積木沙盤、3D 等角視角、可縮放。明亮但不刺眼，建築像精心搭建的展示模型，戰鬥仍清楚可讀。所有建築、人物、動物、植物、地形、船隻、攻城器械遵守同一套積木語言。使用自製資產，不貼官方品牌標誌、現成套組包裝或原作貼圖。

## 積木規格
- 建立固定 stud pitch、plate height、brick height、角度、倒角半徑、色板與比例常數，不拉伸積木填洞。
- 元件含磚、薄板、平滑磚、斜面磚、拱件、圓柱、楔形、鉸鏈、輪子、軸、夾具與透明件。接合必須合理，不任意漂浮或穿模。
- 外露凸點、磚縫、斜面、階梯收邊可辨認；底部管柱／卡榫只在剖面或實際可見位置建模，不為不可見內部製造大量幾何。
- 塑膠材質採輕微表面粗糙差異、合理圓角高光。金屬、透明件與布旗有可辨識差異，但不能整城像鏡面鍍鉻或塗滿髒污。玩家色放在旗幟／盾牌／屋緣，不染滿所有表面。

## 建築與時代
黑暗、封建、城堡、帝王四階段具有一致的演進語彙；不是只更換色相。規劃木柱／簡單坡頂、木石混建／工作台、石牆／拱門／塔樓、精細屋頂／機械與裝飾等輪廓差異。美術升階不能假裝功能科技已研究；資料中的 ageVariant 與 gameplayUpgrade 分開。

每棟建築有清楚入口、合理地基、屋脊、門窗框、工具／貨物、玩家色標誌、陰影接觸。資產細節依建築功能不同；內裝只在入口或剖面可見處製作，不做全部室內。

## 人偶與動畫
採積木人偶式比例、簡化臉部及統一關節系統。村民以斧、鎬、鐮刀、槌與搬運容器表達工作；兵種以盾、矛、弓、劍、騎乘、衣甲和頭飾區分。騎兵馬匹亦為積木造型，武器與手部有 attachment socket。一般戰鬥距離靠輪廓識別，而不是只依賴細小臉部差異。

動畫至少有 idle、walk、work、attack、hit、death／disassemble；需要時有 gather-carry、repair、heal、convert、garrison、embark、pack／unpack。動畫顯示 sim state，不用動畫事件決定傷害。積木人偶不做橡皮般的身體變形。

## 建造、損壞與修復
施工按實際 progress 展示基座→牆柱→屋頂→機能件→旗幟；初始提議五個離散階段，不用透明整棟建築當唯一施工效果。村民站可達的外緣工作，不穿過施工區。受損可顯示局部缺件、少量煙火；倒塌為有限數量裝飾碎片，不能把整棟數千磚都改為動態剛體。修復依 HP 恢復外觀，裝飾殘骸不形成隱藏碰撞。

## LOD 與資產交付
近距離保留凸點／接縫／工具；中距離合併幾何、簡化凸點與武器；遠距離用低模／impostor 但維持兵種輪廓、玩家色與選取尺寸。靜態同材質積木合併；重複元件 instancing；動態人偶使用批次動畫或合適的低成本策略，不能因「instancing」三字就假定骨骼動畫已免費。

交付可重用積木生成器、資產清冊、至少一套完整村落與單位代表資產、LOD／材質預算、模型檢視頁與多角度實際截圖。模型標明單位、pivot、footprint、selectionBounds、collisionProxy、attachment points、動畫清單與授權。

驗收：俯視／斜視／近／遠皆可辨識；門口可通行；無浮空、破面、z-fighting、陰影閃爍；施工作業區與 nav footprint 一致；在一般遊玩縮放仍能區分軍種。占位模型必須明列，不可宣稱已完成高細節美術。

# 04｜地形、資源與戰爭迷霧


建立 seeded map generator 與地圖資料格式，渲染和通行規則分離。

- Tile 資料含 terrainType、height、walkClass、buildability、resource／obstacle refs。陸地、水域、海岸、淺水／特殊地形的通行規則由版本資料決定，不看材質顏色猜是否可走。
- 以積木地台呈現草地、土路、石地、沙岸、高地、懸崖與水域。高度過渡、地圖邊界、河岸、橋接或通道須無裂縫、無浮空。
- 森林樹木、金礦、石礦、野果、獵物、家畜、魚群具獨立 resource state、容量、可採集性、阻擋範圍與耗盡轉換。森林耗盡與建築變化觸發局部導航更新。
- 種子可重現。產生器檢查出生點、初始資源分配、玩家間距、可達性和海岸；公平規則由模式指定，生成失敗有 bounded retries 和可讀錯誤，不能無限卡在 loading。
- 為每個玩家／隊伍管理 unexplored、explored-but-unseen、currently-visible。最後已見建築是帶時間戳的快照，不是持續更新的敵方資料。共享視野由外交與科技規則決定。
- 看不見的敵人不得由模型、血條、選框、minimap、陰影、反射、粒子、空間音訊或事件提示洩漏。已探索區能否顯示已砍樹／建築消失按對照規則實作。
- 單人本機畫面隱藏不等於反作弊。多人伺服器必須過濾敵方隱藏實體；客戶端不可持有其即時位置。

交付至少一張小型手工驗收圖、陸地與海域生成範例、地圖驗證器與 fog debugger。測試多 seed、無路出生點、窄海岸、採光／迷霧邊界、外交變更、失去視野後敵方移動不外洩。

# 05｜尋路、避讓、隊形與卡住恢復


建立確實能支援 RTS 群體移動的導航系統；不能以所有單位直線追目標代替。

- 區分格網通行、粗略區域連通、個體半徑／大型單位、動態阻擋。可採階層式 A* 和局部避讓，演算法選擇需有 workload evidence，不能混用一堆名詞卻無完整行為。
- 命令含 move、attackMove、patrol、follow、stop、queued waypoints、guard／站位命令（按對照範圍）。目標不可達時，回傳明確狀態與附近合法停止點，而不是無限原地抖動。
- 群組有穩定 slot 分配、到達半徑、隊形朝向及前後排規則。狹道收縮、通過後展開；大隊不因最後一名卡住就全部永久停下。
- 動態避讓、穿越友方的允許條件、建築入口／出口、門的開關與外交、採集站點容量、駐軍／運輸集合都需共同規則。
- 建造落地與拆除、砍樹、門鎖、橋／地形變化更新 nav；不得把模型碰撞網格當導航唯一依據。
- 有 bounded replanning、stuck detection、分批計算及取消機制。工作 budget 用確定性的節點數／tick，不用執行毫秒決定 sim 結果；不能瞬移或穿牆當作修復。
- 近戰包圍需要合法攻擊位置，不全部搶同一個座標；遠程單位到達射程後停在可用位置，不能排成穿模堆疊。

測試：百人通過單一城門、雙向窄路、大型攻城器械、採集者圍資源、撤銷長途命令、目的地被新牆封死、船隻靠岸／互相避讓、隊形遇阻後復原。記錄 p95 path nodes、等待 tick 與 stuck 數量；不得宣稱壓力測試通過而只測兩個單位。

# 07｜經濟、村民、採集與交易

交付純 sim 工作流程與積木人物工作／搬運動作連動。驗收村民可完整採集→送返→續採、斷路不無限等待、農田耗盡補種、不足資源拒絕、死亡不憑空入庫、取消不增殖資源、存讀後攜帶量一致。建立資源流量帳，而不是僅看右上角數字上升。

# 08｜建築、施工、人口、升時代與科技樹


將建築、施工與科技製作成資料驅動的完整系統。

- Placement 使用明確 footprint、地形／水岸條件、阻擋／碰撞類別、必要距離與視野規則。施工地基何時阻擋、單位如何離開、何時扣費、失敗是否退款都可測試。
- 施工進度來自實際工作者／效率，連動積木分段搭建；建造者要有可到達工作點。多村民建造、暫停、接手、取消、受攻擊、未完成建築摧毀需具明確規則。
- 人口 used、reserved、cap、hard cap 分開定義。訓練佇列何時扣費／保留人口、人口不足如何等待、房屋被毀、佇列取消退款與出兵出口受阻要處理。
- 生產與科技佇列支援重排／取消的允許範圍、集結點與相依條件；不可一個 frame 重複生產或研究。同種研究不能在兩棟建築重複扣費。
- 四時代升級含資源、前置建築／科技、研究時間與狀態限制；升級完成觸發內容解鎖，但既有單位／建築數值如何更新由 upgrade policy 決定。
- 科技資料含 prerequisite、exclusive group、affected classes、modifier stacking/order、文明可用性、global／local scope、對既有與未來單位的影響。
- 內容類型覆蓋城鎮中心、住宅、資源收集建築、農田、市場、鐵匠舖、兵營、靶場、馬廄、攻城器工坊、學院／大學、修道院、城堡、防禦塔、城牆、城門、碼頭與世界奇觀等；這是系統分類，不代替指定版本的完整建築清單。
- 駐軍／出城、城門開關／上鎖／外交通行、維修、刪除建築、殘骸清理都使用權威命令。射箭／治療等駐軍效果不可只做視覺。

交付建築／科技 schema、樹狀驗證器、建造命令、人口／queue manager、施工視覺對接。驗收前置缺失、同 tick 競爭資源、出口封鎖、城門關閉時單位處理、人口下降、升級前後數值、取消與存讀一致。

# 09｜戰鬥、兵種、彈道與攻城


製作具相剋、位置、射程、科技與命令行為的 RTS 戰鬥，而非只有 attack 減 HP。

- 攻擊資料包含 damage classes、armor classes、base／bonus modifiers、attack interval、windup、range／minimum range、accuracy、projectile policy、splash／piercing、target restrictions。公式需對照 ruleset；未核對的測試公式標示 design_default。
- 近戰攻擊必須可接近合法位置；遠程命中在指定 tick 結算，投射物是權威事件或權威 entity。視覺箭矢可插值但不能在 render callback 決定傷害。
- 移動目標、命中率、彈道科技、高低差、遮擋、友軍傷害、濺射衰減、最小傷害及對建築／船隻／攻城器的特效規則，逐項以所選版本核對並測試。
- 支援近戰步兵、長柄反騎兵、弓手、反遠程單位、騎兵、騎射、攻城車／弩砲／投石類、展開型遠程攻城器、火藥單位、文明專屬單位與海軍等資料類別。具體清單來自 manifest，不固定為少數範例。
- 攻城器有移動／展開／收起／裝填／發射等狀態，並具合適最小射程、轉向與目標限制。駐軍帶來的攻擊或移動影響依資料計算。
- aggressive／defensive／stand-ground／no-attack 等姿態、attack-move、patrol、guard、retaliation、target acquisition、追擊半徑及失去目標後行為需一致。不能看到全圖敵方後自動追殺。
- 治療、回血、轉化、暫時效果與死亡分別處理。死亡同 tick 的命令、人口釋放、乘員、貨物、選取與 AI 引用不可留下 dangling references。
- 戰鬥視覺使用積木武器、盾牌、少量火花、積木解體；不加入未定義的流血、斷肢、每磚護甲或可破壞牆磚新規則。

驗收：近戰接敵、反制兵種、遠程對移動目標、科技前後傷害、不同護甲類別、友軍／中立誤傷規則、攻城展開取消、死亡與轉化競爭、視野外索敵。建立小型可重播戰鬥場景，結果需可追溯到資料與命令。

# 11｜文明差異與完整內容資料化


把文明與內容擴充建立在規則引擎上，而非每個文明複製一套程式。

- Civilization 定義 stable ID、原創顯示名稱／美術組、可用單位／建築／科技、特殊單位、特殊科技、文明加成、隊伍加成、起始條件與覆寫規則。對照名稱映射留在資料／文件中，不以原作素材冒充授權內容。
- 科技／加成需有 selector、operation、value、stacking、priority、scope、appliesToExisting、trigger。不可散落 `if (civName===...)` 無測試分支。
- 團隊加成疊加與互斥、轉化取得單位、出生／升級／死亡時觸發效果、成本變化對已排隊項目的影響都需明確。
- 所有目標文明與單位／科技都有清冊條目，追蹤 data-ready、sim-ready、art-ready、audio-ready、tested。未知總數不能顯示完整。
- 視覺可以按原創文化建築組建立變體，但文明差異必須可在一般縮放辨認且不依賴只改屋頂顏色。不同美術 footprint 與出入口仍符合導航資料。
- 科技樹 UI 自動從資料產生，標示缺少科技、獨有項、前置條件與加成；不可手工畫一棵與 sim 不一致的樹。
- 對每項成本、HP、護甲、攻速、射程、產速等值保留來源、版本和驗證狀態。使用自訂平衡數值的版本標示為原創 ruleset，而非精確 DE 對照。

交付完整內容 validator 與 completeness report generator。至少用兩種結構差異明顯的原創測試文明驗證引擎，再逐項填滿目標清單。驗收每文明可開始、可完成經濟與軍事路徑、無懸空科技、不可用項無法作弊生產、團隊加成與轉化不重複套用。

# 12｜遭遇戰 AI、難度與團隊行為


建立使用同一命令 API 的 RTS AI；不能以定時生成部隊或直接扣敵方 HP 代替。

- AI 只透過該玩家合法 observation 讀取視野／最後情報，預設不偷看全圖、不免費造兵、不繞過前置科技。若另設作弊難度，必須明示並獨立規則。
- 經濟配置：村民生產、資源優先級、人口餘裕、採集點／dropoff 距離、農田與補種、補充被毀經濟、貿易與資源短缺。
- 發展：建築位置可達、科技與時代規劃、對地圖／文明條件調整、偵查與敵方意圖估計。找不到建築位置需有恢復策略，不無限重下同一命令。
- 軍事：依可見情報選擇反制、集結、前線補兵、攻城器配合、分隊、撤退／防守／突襲。海圖要能造船、漁業、運輸與登陸。
- 團隊合作：防守盟友、分配敵人、合法資源支援；遵守外交與視野規則。
- 難度調整觀察頻率、決策間隔、規劃深度、操作預算、策略完整度；不要只有 HP 倍率。固定 seed 時結果可重播。
- AI 決策有結構化 reason／blocked reason，提供 debug panel。Think budget 按 deterministic tick 調度，不能讓某台電腦較快導致 AI 多做決策。

驗收：多 seed 的 AI 自我對戰、資源枯竭、村民大量死亡、卡人口、敵方封路、海圖、被突襲、主基地被毀仍可恢復。記錄完成率、死循環、非法命令與長時間閒置。無實跑的對局不可編造勝率。

# 13｜存檔、讀檔、重播與恢復


設計版本化且可驗證的完整遊戲保存，不是只存玩家資源和單位位置。

- 保存 ruleset／content hash、schemaVersion、map seed 與變更、tick、PRNG、命令排序、外交、迷霧／最後情報、所有單位／建築／資源、工作佇列、交易貨物、人口保留、科技進度、projectiles、timers、AI state、勝利條件與 deterministic path jobs。
- Snapshot 在一致 tick barrier 產生。Worker 與 UI 保存不同步時不得混成一份。引用全以 stable ID 重建，不序列化 Three.js objects。
- IndexedDB local slots、明確 slot metadata、手動匯入／匯出、自動保存上限、配額不足、private-mode／storage denied、舊版本 migration 與損壞檔案提示。
- Replay 記錄初始 snapshot／seed＋有效命令＋必要事件；seek 採 checkpoint，保留玩家視角與 fog；比對 canonical hash。觀戰全圖只在該模式允許時啟用。
- 讀檔要重新建立 render mapping／audio／selection，釋放舊場景資源。存讀後不能多一隻兵、遺失乘員、重領交易金、重複研究或多建一棟房屋。
- 錯誤需可恢復：壞檔不覆蓋好檔，未知 ruleset 不悄悄套用另一套數值。

驗收：採集中、施工中、攻城器展開中、箭矢飛行中、多人轉化競爭中、登船中、遺跡攜帶中、特殊勝利倒數中保存並恢復；續跑相同 ticks 的 hash 對比、migration 失敗、quota failure。多人斷線續局在下一階段另驗收，不以單人讀檔替代。

# 14｜多人、伺服器權威與防資訊外洩


在可重現單人系統上實作真正跨瀏覽器的多人遊戲。預設 server-authoritative，不將尚未驗證的跨瀏覽器 P2P lockstep 當完成。

- 共用 sim package，伺服器驗證命令與所有權，控制 tick、資源、戰鬥、視野與勝利。客戶端只提交意圖，不能直接指定 HP、資源或任意移動座標的結果。
- Lobby 含建立／加入房間、身份／slot／ready、文明／隊伍／地圖／模式／人口／速度設定、版本一致性、開始門檻、離開與踢出政策。不要假設必須依赖原作帳號或官方服務。
- 使用版本化網路協定；命令有 sequence、ack、target tick 與 payload limits。拒絕重送、過期、越權／畸形命令；惡意頻率限制與 schema validation 在伺服器執行。
- 客戶端可以預覽命令、插值可見單位，但不預測隱藏敵人。每玩家 snapshot／delta 依 fog 過濾；不得把全世界狀態送到瀏覽器只在 shader 隱藏。
- 有延遲／抖動／斷線處理、可配置 reconnect window、快照重同步、無效 session 處理、玩家離開／投降／AI 接管政策。暫停權限與背景分頁行為明定。
- 完整 lobby 2–8 slot 為目標；最大單位／人口規模需經量測才能標示支援。八個假 client 可以測協定，不等於八個真實瀏覽器的渲染驗收。
- Spectator 權限、觀戰延遲與資訊範圍獨立；聊天做長度限制和文字安全輸出，不將玩家名稱／訊息插入 raw HTML。
- 提供本地兩 client 啟動、server 設定、TLS／WebSocket proxy／origin／資源上限的部署說明；未部署不宣稱公開房間服務完成。

驗收：兩個獨立瀏覽器完整對局、加入版本不符、惡意改資源、重送命令、延遲／抖動／中斷、重連、擊敗後觀戰、隱藏敵人封包檢查。量測 server tick 與每玩家流量；不得用兩個畫面播放同一段單機動畫冒充多人。

驗收：普通勝利、同 tick 雙方敗北優先序、倒數被中斷、護送目標死亡、合作玩家離線、trigger 儲存恢復、匯入損壞情境、undo 後導航與 fog 更新、整條戰役完成並重新讀取進度。

# 16｜聲音、施工演出與細節整合


把積木世界做成有回應的可玩場景，不讓裝飾淹沒資訊。

- 原創／授權音效類別：UI、選取與命令確認、採集、建造、維修、行走、武器／命中、建築受損、警報、研究／升時代完成、海浪／環境、勝敗與音樂。
- 聲音跟事件／視野／距離對接，offscreen 的己方警報與不可聽的敵方隱藏事件分開處理。設 voice／SFX concurrency、priority、cooldown、volume buses，百人採集不可觸發百個全音量聲音。

- 積木施工依 progress 分段組裝，零件可從場景合法位置短距離吸附；不是每幀生成新 mesh。馬廄、磨坊、鐵匠舖、攻城器、碼頭等 idle／work VFX 依實際工作狀態啟用。

- 日照或純裝飾天氣不改變戰鬥、移速、視野或資源，除非規則清冊明確包含該機制。預設避免大幅景深、強光暈、劇烈鏡頭晃動及遮擋戰場的雨雪。
- 環境微細節限於不阻擋路徑的貨箱、工具架、飼料槽、碼頭纜繩等；有效碰撞物要回報導航，純裝飾物不能暗中卡人。

交付音效來源／license 清冊、事件映射、效果預算、音效壓力場景與 reduced-motion 設定。驗收 mute、首次解鎖、百單位同時事件、霧外聲音洩漏、重開場景後舊音源／particle 清理。缺音檔以未完成註記，不用無聲 stub 宣稱音效完整。

# 17｜內顯效能、相容性與可及性


效能是測試結果，不是加上 LOD 後的口號。暫定目標裝置：中階筆電、16GB RAM、整合式 GPU。

## 場景與目標（提議，尚未實測）
- Smoke：2 玩家、200 個單位、100 棟建築、1000 個資源／障礙實體。
- Main：4 玩家、800 個單位、300 棟建築、3000 個資源／障礙實體，包含同時採集、群體移動、攻城、迷霧與 HUD。
- Stress：8 玩家、1600 個單位、600 棟建築、5000 個資源／障礙實體，用來確認全範圍瓶頸與上限。
上述「單位」是實體數，不等於人口值；每場記錄 idle／moving／fighting 分布與可見數。鏡頭近景／正常遊玩／全圖最大縮放都需測試。

以 1280×720、低品質為第一個量測基線。Main 的初始驗收目標：中位 FPS ≥30、frame-time p95 ≤50ms；20Hz 模擬的 p95 tick <50ms、無持續 backlog。這些是擬定門檻，不是承諾或成果；必要時以實測與使用者同意修訂，但不得無聲縮小範圍。Stress 未達標前，不宣稱完整八人規模已可流暢執行。

## 實作與量測
- 分別量 sim、pathfinding、AI、fog、render、UI、network；記錄 draw calls、triangles、textures／buffers、可取得的記憶體指標與估算方法，不能將 renderer.info 當作完整顯存量。
- 用 LOD／instancing／合併 static geometry、共用材質、骨骼／VAT 或簡化動畫策略、texture atlas、視野／距離剔除、事件節流、資源池、分批資產載入減負載。
- 降級只能改畫面細節、陰影、粒子、裝飾動畫與解像度；不可跳過碰撞／AI／戰鬥、刪單位、修改人口或改亂模擬 tick 語意。
- 先完整載入可玩所需資產，漸進載入高階美術；有 progress、cancel、retry、失敗定位。WebGL context loss、resize／DPR、storage denied、Worker crash、離線／網路中斷可恢復或給明確錯誤。
- 測試桌面 Chrome、Edge、Firefox、Safari；記錄實際版本與 OS。未測瀏覽器標未驗證，不以同引擎推定全部相容。
- 字級、對比、非顏色識別、快捷鍵重設、音量分類、降低動態、關閉邊緣捲動、鍵盤 focus 清楚可見。手機操作不在首版承諾內，不列為已支援。

交付可重跑 benchmark seeds／命令、10 分鐘與長局測試記錄、hard reload 與多次重新開局洩漏檢查、瓶頸排序和實際前後數據。測試環境無 WebGL 或目標機時，保留可執行腳本並明確列出未量測項，不捏造 FPS。

# 19｜首次使用、玩到卡住、修正再測


假設你第一次使用本遊戲，不熟悉快捷鍵與開發者預設。真的從新工作目錄安裝並在可用的瀏覽器操作；若缺少瀏覽器／依賴／目標硬體，明確列出不能驗證的步驟，不把純程式檢查寫成親自遊玩。

額外嘗試：亂按快捷鍵、快速雙擊生產、滿人口、資源不足、拖曳跨 HUD、視窗縮放、切分頁、取消建造、入口被堵、命令目標消失、連續存讀、重連、遊戲結束後再下命令。

修正只觸及必要檔案，增加回歸測試，從原重現步驟再驗證；同時檢查是否引入破圖、穿模、碰撞、迷霧洩漏、音源／GPU 資源洩漏或規則偏差。沒有重測不能標「已修正且通過」。

## 地景細節

地台有一致的積木模數；草地、土路、沙岸與岩地靠結構與色板辨認。樹葉為可批次實例化的模組，樹幹／樹樁表示可採集與耗盡。礦脈可見斜面晶體但不可全用發光材質。水面用少量透明／不透明積木式表現與受控波紋，不為每格水建昂貴透明疊層。裝飾石、花、工具與貨物只放在對讀圖有益的位置。

## 資產生命週期

1. Construction：地基、樑柱、牆體、屋頂、細節與旗幟，初始提議五段。
2. Operational：idle／work，動作與真實生產、資源返還、科技事件連動。
3. Damaged：局部缺件、有限煙火、可讀 HP，而非全棟消失。
4. Destroyed：少量 pooled 積木碎片與短期裝飾殘骸；導航由 sim footprint 變化決定。
5. Repaired／Upgraded：恢復或換代，保留建築身份與指令關係，不丟失 queue。

## 美術驗收

提供正面、側面、斜俯視與遊戲距離的真實模型截圖；正常遊玩、近看與遠看各驗一次。檢查懸空、接縫透光、破面、z-fighting、透明排序、陰影閃爍、選框錯位、入口阻擋、裝備穿模、不同時代混亂與玩家色不足。

LOD 的視覺切換可平滑，但不可在切換時改碰撞、射程、視野或選取權。外觀不影響權威規則，除非 manifest 明確定義。

# 如何判斷「完整玩法移植」

## 四種不同的完成度

| 層級 | 完成條件 | 不能當替代證據的事 |
|---|---|---|
| 機制完整 | 固定版本的每項目標玩法、例外與互動均可執行並驗證 | 有按鈕、有類別、有註解、只會模擬 happy path |
| 內容完整 | 指定文明／兵種／建築／科技／地圖／模式等逐項核對，不存在未說明缺項 | 只做兩文明或幾個代表模型後宣稱原作全部內容 |
| 美術完整 | 資產清冊的模型、LOD、工作／戰鬥／施工／受損狀態及玩家辨識均完成 | 靜態場景截圖、盒子占位、只有材質改色 |
| 品質完整 | 操作、存讀、重播、多客戶端、目標硬體與長局測試達到已同意門檻 | 單元測試數、程式可編譯、未執行的 benchmark |

精確原作對照還需要指定 version/build、資料來源與對照測試。版本或完整清單未知時，不存在可誠實計算的「100% 原作覆蓋率」。

## 核心驗收路徑

- 經濟：採集→攜帶→返還→建造→擴人口→升時代→研究→造兵。
- 戰鬥：偵查→合法接敵→相剋／射程／科技→攻城→防守／撤退→勝敗→再開局。
- 海圖：漁業→海軍→運輸登陸→跨海勝利，含乘員與海岸失敗情境。
- 宗教／交易：治療／轉化→所有權與人口／科技更新；遺跡存入→產出／勝利；商隊→實際往返收益。
- 複雜狀態：途中存讀、相同命令重播、城門／科技／人口／招降／運輸互動。
- 多人：獨立客戶端、權威驗證、fog 封包過濾、延遲與斷線重連、完整對局。
- 模式／創作：原創戰役進度、情境編輯／匯出／匯入／playtest、特殊勝利與 trigger 恢復。

## 標籤規則

- Prototype：工程／美術概念驗證。
- Vertical slice：一條可玩的完整閉環，內容和規模明確有限。
- Feature-complete for agreed scope：已確認清單的系統功能完整，內容／品質仍可有明示缺口。
- Complete for pinned ruleset：固定範圍的內容、規則、美術和品質全部達標，有可重跑證據。

原創戰役驗證戰役系統，不等於原作故事全部重製；自訂平衡數值支援遊戲，不等於與 DE 數值相同；多人房間支援協定不等於已驗證最大人口規模。

## 不允許的完成度灌水

不能把 block 的功能改成 excluded 後宣稱 100%；不能以新增文件取代要求的程式；不能將 graphics placeholder 標為高細節完成；不能把「未發現 bug」說成「沒有 bug」。沒有真實執行的測試，只能列 planned／not_run。

# 模板使用說明

`feature-ledger.csv` 目前有 152 筆「提議的系統／品質檢查項」，全部未實作；它不是已核對的原作完整文明／兵種目錄。真正內容全集必須按所選 version/build 另行展開。

- scope_status=proposed：尚待範圍固定，不能自動當作使用者已同意刪減。
- reference_status=unverified：需要原作規則來源或對照證據。
- reference_status=design_proposal：本包提出的工程／原創美術規格，不代表原作機制。
- implementation_status=not_started：未實作。其餘狀態可用 in_progress、implemented、verified、blocked。
- implementation_files、test_ids、runtime_evidence：實際完成後填入；不能用描述性文字代替真實路徑或結果。

JSON 是「清冊範例」而非完整遊戲資料庫或 JSON Schema。null 是刻意保留的未知／未製作值，禁止當作原作數值 0 或無該項。`qa-result-template.md` 提供各種測試的證據欄位。
