你是一位資深 2D RPG 遊戲工程師、遊戲系統設計師與像素美術整合工程師。
請開發一款受經典 Pokémon 的原創怪獸收集 RPG。
不要只製作畫面展示、假戰鬥或可以走動的地圖。
成果必須具備能從新遊戲一路玩到完成首領挑戰的完整遊玩流程。
【一、平台與技術】
平台：桌面與手機瀏覽器。
形式：2D 俯視角、單人、回合制戰鬥。
技術：TypeScript、Vite、Phaser。
測試：Vitest；瀏覽器流程使用 Playwright 或等效工具。
不包含多人連線、交易、登入、付費系統或 3D 開放世界。
規則引擎不得依賴 Phaser 或 DOM。
內容資料、規則引擎、畫面、輸入與存檔必須分層。
不要將全部程式集中在單一檔案。
【二、首版內容】
四張相連的小地圖：
新手村、草地道路、森林、挑戰場。
八種原創怪獸，初始怪獸提供三選一。
十二個具有實際效果的招式。
三種屬性，提供明確的相剋表。
至少一條兩階段進化路線。
提供教學 NPC、治療 NPC、商店 NPC 與一位首領。
提供捕捉道具、HP 回復道具與基本金錢系統。
不得將尚未實作的功能顯示成可以使用的選單。
【三、完整遊玩流程】
新遊戲
→ 操作教學
→ 選擇初始怪獸
→ 取得捕捉道具
→ 探索草地
→ 野生遭遇
→ 戰鬥與捕捉
→ 回村治療及補給
→ 探索森林
→ 完成挑戰資格
→ 擊敗首領
→ 通關畫面
→ 繼續自由探索
每一階段都需要清楚的引導、解鎖條件與完成判定。
首次遊玩的玩家不應需要閱讀原始碼或額外說明才能通關。
【四、探索與操作】
採用固定格子的移動方式，明確設定格子尺寸。
支援：
方向鍵與 WASD 移動。
Enter 或 Z 確認及互動。
Escape 或 X 取消及開關選單。
手機提供方向鍵、確認、取消與選單按鈕。
角色不得穿越牆壁、樹木、水域或 NPC。
互動需要檢查距離與面向。
只有成功走入可遭遇的草地格子時才進行遭遇判定。
原地不動、撞牆、對話與選單操作不得觸發遭遇。
完成戰鬥後提供短暫的步數保護，避免立即再次遭遇。
地圖切換需要指定目的地、座標與朝向。
所有入口與出口均需檢查落點安全，避免反覆傳送。
【五、遊戲狀態管理】
明確區分：
探索、對話、選單、場景切換、戰鬥、結算與通關。
任何時刻只能由當前狀態接收對應操作。
對話中不能移動，戰鬥中不能操作世界地圖。
快速連按不得重複觸發對話、戰鬥、購買或場景切換。
【六、怪獸與內容資料】
分開設計物種資料與怪獸個體資料。
物種資料包含：
物種 ID、名稱、屬性、基礎能力、招式學習表、
進化條件與素材參照。
個體資料包含：
唯一 ID、物種 ID、暱稱、等級、經驗值、
目前 HP、狀態、已學招式與剩餘使用次數。
同物種的不同個體必須擁有獨立狀態。
招式資料包含：
ID、名稱、屬性、威力、命中率、使用次數、
優先度、目標與附加效果。
提供內容驗證，檢查重複 ID、缺失素材與不存在的資料參照。
【七、回合制戰鬥】
實作單對單戰鬥。
玩家行動包含：
使用招式、使用道具、交換出戰怪獸、逃跑。
敵方必須根據實際可用招式與目前狀態選擇合法行動。
明確定義：
傷害、命中、屬性倍率、速度排序、優先度、
平手處理、狀態效果、逃跑與替代招式規則。
上述公式可以簡化，但必須文件化為本遊戲自訂規則。
回合流程：
收集行動
→ 驗證合法性
→ 排序
→ 逐一執行
→ 每次行動後檢查倒下與戰鬥結束
→ 回合末效果
→ 強制換怪或下一回合
已倒下的怪獸不得繼續行動。
捕捉成功或戰鬥結束後不得再執行剩餘攻擊。
HP 與招式使用次數不得低於零或超過上限。
招式耗盡時仍需提供合法替代行動，不能卡死。
所有亂數透過可注入、可設定種子的介面取得，
以支援可重現測試。
【八、捕捉、隊伍與培育】
只允許捕捉野生怪獸。
訓練家與首領的怪獸不可捕捉。
捕捉機率由剩餘 HP、捕捉道具及狀態等因素決定。
提供明確公式與機率上下限。
捕捉嘗試會消耗一個道具與一次行動。
成功後立即結束該場野生戰鬥。
隊伍上限六隻。
隊伍滿員時，新捕捉怪獸送入基本收納系統。
不得覆蓋、遺失或重複新增怪獸。
勝利後依已定義規則分配經驗值。
支援升級、能力更新、學習招式與進化。
招式欄位滿時，提供替換或放棄學習的流程。
圖鑑區分「已見過」與「已捕捉」。
【九、NPC、商店與世界進度】
教學 NPC 提供操作與目標引導。
治療 NPC 恢復隊伍 HP、狀態與招式使用次數。
商店支援購買、數量選擇、餘額與背包更新。
餘額不足時不得完成交易。
任務與世界事件使用明確的旗標管理。
首領勝利與一次性獎勵必須能防止重複領取。
全隊倒下時：
結束戰鬥、返回村莊治療點並恢復可操作狀態。
不得因缺少道具、全隊倒下或關閉對話，
造成無法繼續遊玩的永久卡關。
【十、UI、美術與音效】
採用一致的原創像素美術。
角色、怪獸、地形與介面必須使用一致的比例與風格。
角色提供四方向移動動畫。
怪獸提供戰鬥正面、背面與隊伍小圖示。
不同怪獸需要可辨識的輪廓，不可只改顏色。
提供：
對話框、戰鬥指令、HP 與經驗條、隊伍、
收納、背包、圖鑑、商店、設定與存檔介面。
提供攻擊、受傷、捕捉、升級、進化及倒下回饋。
所有素材必須隨專案交付，不依賴失效的外部圖片連結。
可以使用原創 SVG、程序化像素素材或本地素材檔，
但不能用占位方塊冒充完成的美術。
手機控制區域不得遮住重要資訊。
文字與數值不得溢出介面。
音效需能關閉，並在使用者互動後才啟用。
提供減少動態效果設定。
動畫不得決定遊戲結果。
跳過動畫或減少動態效果時，規則結果必須一致。
【十一、存檔】
保存：
資料版本、角色位置、地圖、隊伍、收納、
背包、金錢、圖鑑、任務旗標、已擊敗對手與設定。
首版只在安全的探索狀態進行存檔。
戰鬥結果完成後，相關資料需一次提交。
戰鬥途中重新整理，回到戰前的一致快照。
不得出現道具、經驗值或捕捉結果只寫入一部分的情況。
讀檔需驗證格式、數值範圍及資料參照。
損壞存檔不得造成白畫面，也不得靜默覆寫原資料。
提供錯誤提示與重新開始選項。
【十二、測試與驗收】
測試必須覆蓋：
地圖碰撞與安全傳送。
站立及撞牆不觸發遭遇。
四種戰鬥行動的合法性。
先手擊倒對手後，對手不再攻擊。
招式耗盡時仍能繼續遊玩。
捕捉成功與失敗的道具消耗。
隊伍滿員後的收納處理。
經驗值、升級、學招與進化。
全隊倒下後的恢復流程。
商店餘額不足。
一次性獎勵不可重複取得。
讀檔後世界進度一致。
損壞存檔處理。
快速連按不產生重複事件。
手機操作與介面溢出。
另外提供固定測試種子的完整流程測試：
新遊戲 → 初始怪獸 → 戰鬥 → 捕捉 → 治療
→ 森林任務 → 首領 → 通關 → 讀檔驗證。
【十三、交付】
提供完整專案檔案、素材、內容資料、README 與測試。
README 必須列出：
安裝、啟動、型別檢查、測試、建置方式，
以及操作說明、自訂遊戲規則與已知限制。
實際執行環境允許的建置與測試。
有錯誤就修正後重跑。
清楚區分：
已執行並通過、已執行但失敗、未能執行。
不能將未執行的瀏覽器驗收或手機測試宣稱為通過。
不能用假資料展示或預設勝利取代真正的遊戲邏輯。
