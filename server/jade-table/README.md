# 青雀真人麻將

頁面：`/web/127-jade-table.html`，遊戲敘事分類。單人與真人共用 `assets/jade-table/engine.mjs`；房號、身份、洗牌、出牌、搶牌與計台由伺服器裁定。只傳各玩家可見的牌。

## 執行與驗證

需要 Node.js 22 以上。根目錄執行 `npm ci`，再 `npm start`，開啟 `http://127.0.0.1:8127/web/127-jade-table.html`。未提供資料庫時只有本機記憶體模式。

`npm run test:mahjong` 驗證行牌／結算與跨實例四人房、手牌保密、越權拒絕和重連。若 `.env.local` 已有 `DATABASE_URL`，執行 `node --env-file=.env.local --test server/jade-table/game.test.mjs` 可驗證真實 Neon；測試只新增隨機房間，兩小時後失效。

## Vercel + Neon

1. 在 Neon 執行一次 `schema.sql`，建立專用 `jade_mahjong_rooms` 表。
2. 在 Vercel 的 htmls 專案 **Production** 環境設定 Secret `DATABASE_URL` 為 Neon 提供的連線字串；不可加到前端或 Git。
3. 從根目錄部署。`api/jade.mjs` 提供 `/api/jade` WebSocket，前端使用同網域，無需另購後端主機。
4. 部署後用四個獨立分頁開好友房、輸入六位房號、開局。可勾選 AI 補位；真人不足四人且未勾選則等待。

Vercel 的 WebSocket 為 Beta，每條連線在 Function 最長執行時間（預設 300 秒，Hobby 上限 300 秒、Pro 可到 800 秒）一到就會被關閉。前端每 200 秒（背景分頁的計時器可能延遲，所以留足餘裕）先開新連線、以 RECONNECT 接手席位，再關掉舊連線，所以正常情況不會看到斷線；意外斷線會在 150 毫秒內重連，2.5 秒內不顯示斷線訊息，期間按下的操作會排隊，重連後才送出。伺服器至少每 5 秒推送一次狀態，前端 12 秒沒收到訊息就視為連線已死並重連。各實例的每秒計時只在有事要改（輪到誰、AI 動作、接手、每 10 秒更新在線時間）時才寫入 Neon，閒置時只讀取，避免和玩家操作搶版本；版本衝突重試會隨機退避。房間存於 Neon，以版本條件更新避免多實例同時改牌局。房間在最後活動兩小時後失效，房號可覆用；舊資料不持續提供查詢。部署後沒有連線的房間會停止主動計時，重連時從已存狀態恢復並處理超時。無永久牌譜／觀戰／帳號排名。

同時開多個分頁時每頁各有自己的 sessionStorage 重連身份。斷線保留30秒，之後 AI 接手；明確離房立即由 AI 接手。積分不涉及現金。

好友房有「茶敘」聊天：入座的真人以 `CHAT` 送出 1 至 60 個可見字元（emoji 算一字；每人 0.8 秒一句），訊息寫進房間資料，跨實例一樣靠每秒輪詢送達。前端把要送的話排隊、一次一句，逾時以同一個 `cid` 重送，伺服器以 `cid` 去重並回 `CHAT_OK`，冷卻中則回帶 `retry` 的錯誤讓前端稍後再送，被拒的話放回輸入框。新訊息在發言者座位上浮 5 秒（同一人連講疊兩句），聊天面板由右下角「茶敘」開合並顯示未讀數，打開時在桌機與橫向佔右側一欄、手機直向佔底部一條，3D 牌桌與操作列在剩下的空間重新排版，所以不會蓋到任何牌；結算與大廳對話框開著時面板移進對話框。Q 版表情貼圖走同一條路：`CHAT` 帶 `emote`（`smug`／`cheer`／`shock`／`sweat`／`cry`／`rage`，白名單在 `assets/jade-table/emotes.mjs`），伺服器忽略前端的 `text`、自己寫成「〔得意〕」這類記錄文字並保留 `emote` 欄位，前端收到後在座位上彈出該角色的 Q 版貼圖而不是文字泡泡；冷卻、去重與當天記錄規則都和一般訊息相同。AI 座位的表情是各前端依牌局事件（鳴牌、聽牌、胡牌）以局數、`actionId` 與絕對座位雜湊決定，不經伺服器，同房每個人看到的一樣。聊天也會觸發 STATE_SYNC，所以出牌後前端要等 `DONE`（或錯誤、或輪次改變）才解鎖按鈕。只保留台灣時間當天的記錄：過午夜的舊訊息會在下一次計時寫入時從房間刪除，也不再送出；每條連線只送尚未送過的訊息，重整或換線時補回當天記錄。房間本身兩小時未活動仍會失效。
