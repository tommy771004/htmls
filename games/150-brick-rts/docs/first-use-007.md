# 首次使用修正迴圈 007：城鎮中心入口與權威占地

2026-09-25，C 階段「入口、作業區與權威占地一致」的可玩里程碑，不是完整 RTS 對局。

環境：Node 22.23.1、Darwin 27.0.0 arm64、Chromium 151.0.7922.34。seed 260925，ruleset `f4bf3eb9`，State／snapshot v10。

## 這個里程碑改了什麼

- 正式沙盒兩方的起始建築從住宅改成城鎮中心，位置是 (265,350) 與 (1065,350)。拱門中心落在導航格線 x=400／1200，面向出生點，距出生點 65 單位。
- `packages/content/footprints.ts` 的碰撞改成「每種障礙物一組矩形」：
  - 城鎮中心只有石柱、木柱、拱門兩翼、公告板、貨箱和旗桿會阻擋。地基、大廳、拱門開口、門前鋪面和開放的後側都可以走。
  - 其他七種障礙物仍是原本的單一矩形，數值沒變。
  - 住宅仍是整塊阻擋，它的門只是外觀，不能進入。
- 拱門兩翼的碰撞比看得見的開口窄。原因是依據實際村民外形計算：肩寬 0.46、頭頂 1.13，站上 0.16 的地基後，中心偏離超過 0.135 帽緣就會擦到拱頂的弧線。這個值和模型用同一個 `archOpening()` 公式算出，有測試鎖定。
- 模型調整：
  - 城鎮中心拱門固定為 1.4×1.6，大廳加高。
  - 原本高出地基的三階石階會讓人偶腳陷進去，改成與地基齊平的鋪面。
- 渲染：人偶身體和城鎮中心地基重疊時會抬高 0.16。這只影響外觀，不影響模擬結果。
- 迷霧：建築只要有任一占地格被看見就記錄，不再只看左上角的錨點格。
- 版本識別：占地契約併入 rulesetHash，State／snapshot 升為 v10。v9 存檔會被明確拒絕，沒有做遷移。

## 實際流程

乾淨目錄中執行同內容的腳本；之後收進 `tests/first-use-gate.mjs`（`npm run test:first-use`），並在工作目錄重跑通過。全程用滑鼠在 3D 畫面上點選，不透過座標輸入欄：

1. 首次進站：131 ms 可以操作。
2. 「開始模擬」在首屏內，位於場景上方。
3. 點人偶身體選取村民 2。
4. 點城鎮中心門前鋪面 → 抵達 (4.0, 6.0) 待命。
5. 點屋頂下的大廳地面 → 村民穿過拱門，抵達 (4.0, 4.2)。
6. 點石柱 → 被拒絕，狀態指紋不變。
7. 在大廳後方連點兩次 → 穿過大廳抵達 (4.0, 2.8)。
8. 儲存 → 重建 → 讀取：指紋一致；重播 119 ticks 也一致。
9. 390 寬下沒有水平溢出；過程中沒有 pageerror、console.error 或外部請求。

截圖與記錄在 `test-results/`：`fu7-gate-front.png`、`fu7-inside-hall.png`、`fu7-behind-hall.png`、`fu7-390.png`、`fu7-log.json`。另外人工看過多角度的近拍，村民站在拱門中與大廳內都沒有擦到拱頂或石柱。

## 界線與下一步

城鎮中心目前只是一個靜態障礙物，但有真的可以走進去的入口。它不生產、不收資源、不能駐軍，也沒有集結點，畫面上也沒有提供這些按鈕。

作業區（建造者或採集者站在建築外緣的工作點）要等 E 階段施工與送返接入才有意義；目前只驗證入口與大廳可達。

多人同時通過窄門、雙向通行、大型單位（騎兵高度會擦到拱頂）和動態阻擋都屬於 D 階段的 05。C 仍是 in_progress：美術元件庫、細節矩陣與剩餘資產還沒完成。
