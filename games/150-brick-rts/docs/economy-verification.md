# B 階段：資源交易與接收時間重播

2026-09-25。本輪新增權威模擬能力，沒有新增建造或訓練 UI；不能將資源預留稱為已完成生產玩法。

## 已實作

- 每個玩家持有四資源帳戶、已用／預留人口、預留紀錄。
- reserve 在目標 tick 全部驗證後一起扣款；取消按原紀錄退款且只執行一次。
- 同 tick 多筆預留依既有穩定順序處理。資源不足留下帶 tick／player／sequence 的失敗結果，不部分扣款。
- 玩家不能取消敵方預留；未知內容在接收前拒絕。
- 命令紀錄新增 acceptedTick。重播按原接收時刻逐步恢復，而非在 tick 0 一次灌入所有命令。
- 帳戶、預留、失敗結果及接收時刻均納入 state/hash。snapshot 升為 v3，舊檔明確拒絕，不偷偷解讀成新版。

## 實際測試

`npm run build` 通過；`npm test` 共 28 tests，28 pass。新增案例涵蓋：

1. 木材足夠、石材不足時，所有資源都不扣。
2. 人口不足時資源不扣。
3. 取消退款一次；重複取消與完成後退款拒絕。
4. 同 tick 五筆村民資金預留，只有四筆成功；食物為零而非負值。
5. 跨 tick 扣款→退款→再次扣款，存讀續跑與原接收時間重播一致。
6. 取消敵方項目／未知內容不改命令紀錄。
7. 退款超過安全整數範圍時完全不改帳戶。

既有桌機 1440×900 與手機 390×844 瀏覽器回歸通過：首次進站、選取、指令、固定占地繞行、存讀、重播、Worker 中斷／逾時恢復、規則驗證及首頁搜尋。正常流程沒有 pageerror／console.error／外部請求／水平溢出。Node 22.23.1，Chromium 151.0.7922.34，darwin arm64。

本輪沒有新增可玩經濟流程，故沒有把核心交易測試寫成提示 19 的採集→送返→建造→勝敗通過。上一輪首次可玩里程碑仍為 first-use-003.md；下一個 C 階段可玩里程碑需再從乾淨目錄首次進站驗收。

## 範圍與下一步
