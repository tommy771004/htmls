# 首次使用修正迴圈 018：prompt 19 完整路徑與 E 階段結案

2026-09-26。對照 prompt 19 的測試路徑，補齊缺少的部分，並以一般模式、對電腦的方式實際走完整條路徑。

prompt 19 的路徑：首次進站 → 等待／失敗重試 → 設定畫質與音量 → 建立對局 → 找出村民 → 採木與採食物 → 送返 → 造房 → 造軍營 → 升時代 → 造兵 → 偵查 → 攻擊 → 撤退／治療 → 勝敗 → 再開局。

## 補上的真實行為

- **設定**（選單）：
  - 畫質三級：高是銳利畫面加 2048 柔和陰影，中是 1 倍像素加 1024 陰影，低是 0.75 倍像素、無陰影。
  - 音量 0–100，0 為靜音。
  - 兩者都存在這個瀏覽器，重新載入後保留；儲存被封鎖時使用預設值。
- **音效**：
  - 全部用 WebAudio 即時合成（振盪器音符與濾波雜訊），沒有音檔，也沒有網路請求。
  - 涵蓋選取（村民與士兵不同）、下令、攻擊令、放置、完工、生產、受擊、警報、升時代、勝利、戰敗、建築倒塌與投降。
  - 每種音效都有最短間隔，混戰時不會疊成噪音。音訊在第一次點擊或按鍵後才啟動，符合瀏覽器的自動播放規則。
- **「,」選取全部軍隊**：民兵與弓手，不含斥候與村民。
- **移動到看不見的障礙物上**：
  - 以前會被拒絕（「目標位於建築、資源……」），而且這個訊息會洩漏迷霧中的地形。
  - 現在單位會走到最近的空地，和原作相同。

## 實際流程（`npm run test:full`，一般模式，曠野，對電腦，4×，只用滑鼠、鍵盤與小地圖）

1. **首次進站**：遊戲自動開始。
2. **設定**：畫質改為低（畫布的 `data-quality` 為 low）、音量 30%；重新載入後兩者都保留。
3. **建立對局**：從選單選曠野、紅方電腦、種子 260925，按「開始新遊戲」。
4. **採集與建造**：
   - 按「.」找出村民，右鍵野果。
   - 第二名村民造房（Q），第三名造軍營（W）。
   - 再按 W 時，提示「兵營：木材不足：需要 150，目前 20」。
5. **送返與分工**：食物入帳 210；住宅完工，人口 4/10。完工後，兩名建造者分別去採木與採金。
6. **升時代**：食物到 300 後，按 H 選城鎮中心，研究第二時代並完成；採野果的村民接著蓋農田。
7. **造兵**：在兵營快速雙擊弓手，一次排入 2 項；陸續共 4 名弓手，人口 9/10。
8. **偵查**：點選斥候，右鍵小地圖的遠方；目標在看不見的樹上，照樣前往。之後迷霧記憶出現「紅方城鎮中心」。
9. **攻擊、撤退、再攻擊**：
   - 按「,」選取全部軍隊，右鍵紅方城鎮中心。
   - 2.5 秒後右鍵小地圖把軍隊撤回家，再次攻擊。
10. **勝敗**：
    - 軍隊被紅方的防守部隊消滅後，從選單投降：戰敗，08:45，「你已投降」。
    - 這是第一次玩的玩家可能遇到的正常結局；另一個流程 `test:match` 驗證的是獲勝的結局。
11. **結束後再下命令**：右鍵地面，提示「對局已結束：按『再開一局』開始新遊戲」。
12. **再開局**：成功。

過程中實際播放的音效：下令、選取村民、放置、完工、升時代、生產、選取士兵、受擊、攻擊令、警報、投降。沒有 pageerror、console.error 或外部請求。

「等待／失敗重試」由 `test:browser` 的 Worker 失敗、重試與恢復情境涵蓋。

## 問題與修正

| 編號／嚴重度 | 重現與根因 | 修正與重測 |
|---|---|---|
| FU18-1／高（卡住、洩漏資訊） | 偵查時，右鍵小地圖的遠方被拒絕，因為目標剛好在迷霧中的一棵樹上。玩家看不到那棵樹，拒絕訊息反而透露了它的存在。 | 移動改為走到最近的空地（集結點仍維持拒絕）。單元測試：落在障礙物內的移動會被接受，單位停在 150 以內的空節點。偵查重跑成功。 |

| FU18-3／低（測試） | 第一版流程在重新載入時開了新的瀏覽器環境，設定當然不在；「資源不足」步驟當時木材其實足夠；「結束後再下命令」點到了結果對話框。 | 流程改用同一個瀏覽器環境；在木材剩 20 時才按 W；點選戰場角落。三者都重測通過。 |

## E 階段結案

建置順序對 E 的要求：能發展經濟、升時代、造兵、攻城、判定勝敗、再開局，並以雙方的小範圍資料起步，明確標示為垂直切片。

- 玩家端由 `test:full` 走完整條路徑。
- 獲勝的結局由 `test:match` 涵蓋。
- 電腦端由單元測試涵蓋：經濟、升時代、造兵、進攻、征服，以及認輸。

`stage-dependencies.json` 把 E 標為 `vertical_slice_verified`，並記下未完成項；F 成為進行中的階段；C 與 D 仍是延後的 in_progress。治理測試也隨之更新。

## 未驗證項

- **治療**：需要僧侶，屬於 F 階段，目前沒有。
- **實機效能**：實際 GPU 的幀時間仍未量測。
- **音效**：無畫面瀏覽器聽不到聲音，只驗證了播放紀錄與音訊狀態，沒有人工試聽。
- **電腦的難度**：很基本（不撤退，失去城鎮中心就認輸）；第三、第四時代沒有內容。
