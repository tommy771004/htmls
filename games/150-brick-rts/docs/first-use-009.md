# 首次使用修正迴圈 009：採集、攜帶與送返

2026-09-25，E 階段第一個可玩里程碑：經濟循環的第一段。這不是完整對局。

環境：Node 22.23.1、Darwin 27.0.0 arm64、Chromium 151.0.7922.34。seed 260925，ruleset `312073eb`，State／snapshot v12。

## 新增的真實行為

- **採集命令**：`gather {unitIds, resourceId}` 可派村民採集樹木、石礦、金礦、野果。
- **工作循環**：前往採集點 → 逐 tick 採集 → 裝滿 10 單位送回己方城鎮中心 → 回來繼續。資源耗盡時，先送回身上的貨，再轉往 600 以內最近的同類資源；附近沒有就閒置。
- **流量帳**：帳戶記錄累計採出與送返量。測試每個 tick 都檢查「採出 = 送返 + 身上攜帶」，且「庫存 = 初始值 + 送返」。
- **中斷規則**：移動或停止命令會結束工作，但保留身上的貨；對不同種類的資源下採集命令，會先把身上的貨送回。
- **HUD 與畫面**：
  - HUD 的食物／木材／黃金／石頭與人口，直接讀 Worker 投影的己方帳戶。
  - 選取清單顯示工作階段與攜帶量。
  - 人偶依模擬狀態動作：採集時面向資源、拿對應工具（木材用斧、石頭與黃金用鎬、野果用籃）；送返時手提籃子，雙腳照常擺動。
- **操作**：右鍵點資源就是採集。狩獵、放牧、捕魚點下去會明確回報「尚未實作」，沒有拿靜態食物點冒充。
- **鏡頭**：點過場景後，方向鍵平移鏡頭，平移方向跟著鏡頭旋轉，並限制在地圖範圍內；F 對準選取的村民。點頁面其他地方後，方向鍵恢復捲動頁面。
- **規則數值都是 design_default**：攜帶 10；每單位的採集 tick：食物 20、木材 20、黃金 25、石頭 25；工作點與送返點的距離範圍各 50。三名村民採同一棵樹，90 秒約送回 130 木材。

## 實際流程（`npm run test:economy`，乾淨目錄）

全程用滑鼠與鍵盤；資源在畫面上的位置由同一個 seed 的地圖算出。

1. **首次進站**：HUD 顯示「食物 200 · 木材 200 · 黃金 100 · 石頭 100 · 人口 3/40」。
2. **採木**：框選三名村民，右鍵點最近的樹，提示「村民 1、村民 2、村民 3 前往採集」。開始模擬後依序進入「採集中」。
3. **第一次送返**：木材 200 → 210。
4. **採野果**：只點選村民 3，右鍵點野果；食物 200 → 210，同時木材持續增加到 248。
5. **獵物被拒**：右鍵點獵物，回報「狩獵尚未實作」，村民 3 的工作不變。
6. **停止保留貨物**：按 S，村民 3 待命，仍「攜帶食物 1」。
7. **存讀與重播**：儲存 → 重建（木材回到 200）→ 讀取，HUD 與指紋完全恢復；重播 823 ticks 一致。
8. 沒有 pageerror、console.error 或外部請求。

另外在工作目錄拍了近照（`economy-gather-facing-close.png`）：三名村民背對鏡頭、面向樹木、手持斧頭，放大後城鎮中心與資源都能用平移看到。

## 未驗證項

- 目標硬體效能。
- 村民死亡時身上的貨如何處理：目前還沒有死亡機制。
- 超過工作點數量的村民：一棵樹約有 11 個工作點，測過 5 名同採一棵樹都能採滿送回；超過工作點數時會在既有工作點旁等待，沒有測過。
- 人偶工具與姿勢只看過近照，沒有逐幀檢查穿模。
- 敵方經濟：紅方還沒有 AI，也不會採集。
